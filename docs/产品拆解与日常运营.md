# 旅声：从客人反馈到门店改进

这是一套面向酒旅从业者的工作方法和轻量工作台。目标是让老板、店长、前厅和运营对同一条反馈有共同记录，能回答“发生了什么、谁在处理、处理到了哪里、以后怎样减少同类问题”。

## 一、谁需要什么

| 角色             | 每天要回答的问题                       | 对应入口                     |
| ---------------- | -------------------------------------- | ---------------------------- |
| 业主、总经理     | 有无安全事件、集中投诉和长期未处理问题 | 当班聚焦、红橙风险、大盘     |
| 店长、值班经理   | 哪些内容需要核实、派给谁、何时回复     | 待处理列表、详情、处置时限   |
| 前厅、客服、运营 | 原话和链接是什么，如何按真实情况回复   | 来源核验、核查记录、回复草稿 |
| 客房、餐饮、工程 | 是偶发补救还是需要持续整改             | 主题聚合、整改台账           |
| 跨班次交接人员   | 之前怎么处理，下一班还要做什么         | 操作记录、简报、备份交接     |

## 二、日常闭环

```mermaid
flowchart LR
  A[授权导出或人工登记] --> B[导入预览与去重]
  B --> C[规则初判]
  C --> D[打开原内容核验]
  D --> E[确认负责人]
  E --> F[实际处置与回复]
  F --> G[复盘与整改]
  G --> H[检查后续同类反馈]
```

建议在交班时完成一次固定动作：补齐当班来源数据，先核对红橙风险，再处理普通咨询，最后把未完成事项和整改项写入简报。频率取决于门店规模和现场情况，页面不会替代值班安排。

## 三、先分清三类反馈

- **风险与负面**：卫生、设施、噪音、预订退改、服务、安全、停车接驳，以及景区演艺取消等。规则只提示线索，事实由负责人核实。
- **咨询**：价格、早餐、交通、儿童权益、营业安排。它们是信息供给的信号，不应直接计为差评。
- **正面与常规讨论**：保留口碑亮点和真实需求，用于服务训练、信息更新和内容选题。

安全与隐私线索优先交由现场负责人核实。记录线上回复不能替代现场应急处置。评分、词语和情绪只是线索，语义复杂、讽刺或上下文缺失时需要人工纠正。

## 四、大盘要回答的问题

大盘把平台来源、情感和处理状态连起来。线条宽度代表已收录反馈条数，可以看到某类负面主要从哪里来、多少仍在待处理、多少已记录复盘。旁边提供待处理、红橙风险、未核验、已闭环的入口。

数字都来自当前对象和选定的时间范围。一个帖子与多条评论会形成多条记录，不能据此声称有多少独立客人。没有可靠城市信息时，不绘制虚构的全国客源热力图。

## 五、怎样确认数据可用

每条记录保留来源标识、原链接、发布时间、收录时间和首次发现。封面与评论截图分开理解；没有原链接和图片时，系统保留缺失状态，不宣称已核验。用户在打开并核对原内容后，才应标记核验。

平台显示“未接入”时，0条只表示未收录。样本负面率与全网口碑不同。仅知道发布日期的反馈可以进入日级统计，不进入小时图；完全未知时间的反馈留在全部历史。

客源城市仅从明确自述提取，并标记为疑似。帖子提及某个城市、发出游玩攻略、使用地名标签，都不足以证明客人来自该地。

## 六、怎样形成真实处置

状态按待研判、已派单、处理中、已回复、已复盘推进。派单要有负责人，已回复要有实际回复或处理结果，复盘要有总结。这里的派单是门店工作记录，尚不向任何群聊或员工自动发送通知。

回复草稿是本地模板。需要核实的内容保留填写位置，不能直接作为“已回复”保存。不要填写尚未确认的退款、赔偿、时效或整改承诺。

来源正文或链接变化后，原核验标记失效并重新进入待研判；旧操作记录仍保留。时限从首次发现开始计算，不用老帖的发布时间替代发现时间。

## 七、复盘不止是把状态点完

对反复出现的卫生、噪音、设施或退改问题，建立独立整改项：写清动作、负责人、截止时间和真实结果。回复了一条差评不等于解决了长期服务问题。台账的完成状态需要记录结果；后续可继续对照同类反馈检查效果。

## 八、当前边界和后续方向

| 能力                             | 当前状态 | 下一阶段需要什么                         |
| -------------------------------- | -------- | ---------------------------------------- |
| 授权数据整理、手工登记、去重核验 | 已实现   | 不同商家的导出样本，用于完善字段映射     |
| 源内容核验、处置保存、整改台账   | 已实现   | 班次责任制度和门店实际执行               |
| 模拟体验、简报、备份恢复         | 已实现   | 定期备份习惯和授权交接范围               |
| 持续采集、群告警                 | 未接入   | 具有使用授权的数据源、后端任务和通知渠道 |
| 多人实时协作、权限、审计         | 未实现   | 服务端存储、身份体系、成员权限和审计策略 |
| 模型语义分析                     | 未接入   | 评测集、隐私边界、预算和人工复核机制     |

当前版本适合小团队先建立可执行的工作闭环。对必须持续采集、多店协作和自动告警的组织，需要在这些基础上建设服务端能力。
